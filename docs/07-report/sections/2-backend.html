2. Backend design: the REST API

2.1 Rules for every endpoint

  • Three services: user-service http://localhost:8081 (Java HttpServer), book-service :8082 and order-service :8083 (Python Flask). They listen on this computer only.
  • JSON in, JSON out. The one exception is the bill, which is HTML.
  • Log in once, then send the token on every request: Authorization: Bearer <token> (N4). book-service and order-service ask user-service who owns it.
  • Roles are checked by the services (N5): a customer cannot reach manager endpoints, and sees only their own orders.
  • One error shape: { "error": "a message a person can read" }, with the status: 400 bad input, 401 not logged in, 403 not allowed, 404 not found, 409 conflict (taken, sold out, or changed meanwhile), 503 another service is not answering.

2.3 Inputs and outputs of the main flows

Real requests and answers, for one customer, alice, and three books from the catalog.

Log in (FR1)

POST /api/auth/login
{ "username": "alice", "password": "alice2026" }

Response 200. A wrong username or password gets 401 "Wrong username or password", the same for both, so it never tells which usernames exist.

{ "token": "3f9a1c0e7b2d...a5c", "userId": 3, "username": "alice", "email": "alice@example.com", "role": "CUSTOMER" }

Search books (FR4, FR5)

GET /api/books?keyword=clean

Response 200: every book whose title or author contains the word, ignoring case.

[ { "id": "655f1c2ab7e4a1d2c3f4a5b6", "title": "Clean Code", "author": "Robert C. Martin",
    "price": 40.0, "copiesAvailable": 4, "category": "Technology",
    "coverUrl": "https://covers.openlibrary.org/b/id/8065615-L.jpg", "ratingAverage": 4.5, "ratingCount": 2 } ]

Place an order: buy two books, rent one (FR6–FR10)

POST /api/orders
{ "items": [
    { "bookId": "655f1c2ab7e4a1d2c3f4a5b6", "type": "BUY" },
    { "bookId": "655f1c2ab7e4a1d2c3f4a5b7", "type": "BUY" },
    { "bookId": "655f1c2ab7e4a1d2c3f4a5b8", "type": "RENT" } ] }

Response 201. The rented book costs 10% of its price (80.00 → 8.00) and is due back in 7 days. The bill is saved as a file and emailed in the background. If any book is sold out, the answer is 409 and nothing is saved.

{ "id": 1042, "username": "alice", "createdAt": "2026-11-18T10:05:00", "paymentStatus": "PENDING",
  "items": [
    { "title": "Clean Code", "type": "BUY", "quantity": 1, "unitPrice": 40.0, "rentDueDate": null },
    { "title": "Database System Concepts", "type": "BUY", "quantity": 1, "unitPrice": 55.0, "rentDueDate": null },

  "total": 103.0, "billFile": "bills/bill-1042.html", "billHtml": "<!DOCTYPE html>...", "emailQueued": true }

Mark an order as paid (FR13)

PATCH /api/orders/1042/payment-status
{ "paymentStatus": "PAID" }

Response 200: the order, now "paymentStatus": "PAID". A customer who tries gets 403 "Only a manager can do this".
