4.3 The patterns it follows

PatternHow it is followed here
Client/serverThe two apps are clients. The three services are servers, reached only over HTTP with JSON. The apps never touch a database.
Three tiersPresentation: Mooney's, Mooney's Manager, and their shared package. Logic: the three services (who may do what, prices, renting, copies, bills, reports). Data: MySQL, MongoDB, and the bill files. Only the logic tier reads or writes the data.
Four layers in each serviceRoutes read the request and write the answer → services hold the rules → repositories read and write the database → models are plain data. A layer calls only the one below. Every service is built the same way, in Java and in Python.
Model-View-ControllerServices: models are the model, routes are the controller, the JSON answer and the HTML bill are the view. Apps: data classes (Book, Order) are the model, screens are the view, and the *Api classes with each screen's state act as the controller. Flutter is built from widgets, so a screen's state both draws and reacts: the fit is loose there.

4.5.1 user-service (Java)

ClassLayerRole
UserServerStart-upBuilds the parts and starts the HTTP server on port 8081
AuthHandler, UserHandlerRoutesLog in, log out, session check; register
BaseHandlerRoutesReads JSON and turns every error into { "error": ... } in one place
AuthServiceServiceThe rules of logging in, sessions, and registering
PasswordHasher, TokenGeneratorServicebcrypt hashes; random 64-character tokens
JdbcUserRepository, JdbcSessionRepository, DatabaseRepositoryThe users and sessions tables, through a connection pool
User, Session, RoleModelPlain data

4.5.2 book-service (Python)

Class or moduleLayerRole
routes.py, schemas.pyRoutesThe 8 endpoints; the checks on each request (BookInput, ReviewInput)
BookService, ReviewServiceServiceSearch, add, change, copies; reviews and ratings
UserServiceSessionCheckerServiceAsks user-service who owns a token
MongoBookRepository, MongoReviewRepositoryRepositoryThe books and reviews collections; copies change in one atomic step
Book, Review, CurrentUserModelPlain data, written as JSON by to_json()

4.5.3 order-service (Python)

Class or moduleLayerRole
routes.py, schemas.pyRoutesThe 8 endpoints; the checks on each request (OrderInput, SalesReportQuery)
OrderServiceServicePlace an order (all or nothing), list, pay, bills
ReportServiceServiceThe sales report of a period
pricing.py, bill.pyServiceThe renting rule (10%, 7 days); the HTML bill and its file
BookServiceCatalog, SmtpMailerServiceTakes copies from book-service; emails the bill in the background
MySqlOrderRepositoryRepositoryThe orders and order_items tables, saved in one transaction
Order, OrderItem, SalesReportModelPlain data

4.5.4 bookstore-ui (shared by both apps)

ClassRole
ApiClient, UserApi, BookApiTalk to the services; turn every failure into one ApiException with a readable message
SessionWho is logged in, and the token
LocalServicesWhen an app opens, starts the three services on this computer if they are not running
Book, Order, ReviewData read from JSON
LoginForm, BillView, BookCover, RatingStars, MooneysSign ...Widgets both apps use, in one look (colors, fonts, light and dark)
